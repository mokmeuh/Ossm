## Findings — mode live (bug 2)

### Chaîne firmware confirmée (lecture code)
- **Config.h** : stepsPerMM=20 (800/40), maxSpeed=1000mm/s=20000 steps/s, maxAccel=50000mm/s²=1e6
  steps/s², commandDeadZonePercentage=1.0.
- **Entrée streaming** (machine.h:71-78) : `streaming [isPreflightSafe] → resetSettingsStreaming +
  drawPlayControls + startStreaming`. Preflight (preflight.cpp:42-43) : pot vitesse PHYSIQUE
  < 1.0 % requis → `Done{}`. Le bouton physique doit être à ~0 pour ENTRER.
- **streaming.cpp (moteur)** : `stepperTranslateFrame(Native)` + DIR false (compense StrokeEngine).
  Boucle : si `speedLimit==0 || accelLimit==0` (speed/sensation settings) → **tous les moves
  ignorés** (log "Spped or accel too slow"). speedLimit=maxSpeed*speed/100, accelLimit=maxAccel*
  sensation/100. `maxStroke = min(stroke,depth)/100*measured` (streaming_logic.h), position =
  scaleStreamPosition. Seuil : timeSeconds>0.01 && distance>1 step.
- **play_controls.cpp** : boucle ~100ms. speed = pot physique, plafonné par speedBLE si
  `USE_SPEED_KNOB_AS_LIMIT` (défaut TRUE board.cpp:4), sinon speedBLE si flag BLE actif. Le flag
  `lastSpeedCommandWasFromBLE` est reset si `|pot - settings.speedKnob| > 2 && pot < speed`.
  **ÉCRASEMENT** : si `session.playControl==DEPTH` (cas streaming après set:depth) →
  `settings.depth = encoder.readEncoder()` chaque tick.
- **OSSM.cpp handlers** : set:speed → flag BLE=true + speedBLE ; set:depth/stroke/sensation/buffer →
  playControl + encoder.setEncoderValue + settings.X ; stream:pos:time → push targetQueue.
- **config.hpp SpeedKnobConfigCallbacks.onWrite** : "false" → `USE_SPEED_KNOB_AS_LIMIT=false`.

### Racines du « le Live ne fait rien »
1. **PRINCIPALE — USE_SPEED_KNOB_AS_LIMIT doit être false** : l'app l'écrit en WRITE_NO_RESPONSE
   sans confirmation ; si l'écriture est perdue (le commentaire code 918-921 admet déjà que celle
   faite à la connexion "peut avoir été perdue"), USE_SPEED_KNOB_AS_LIMIT reste TRUE → speed =
   pot(≈0) → speedLimit=0 → **tous les stream:pos:time ignorés**.
2. **Division par zéro streaming.cpp:64** (`distance/abs(distance)`) : `PositionTime lastPositionTime`
   NON initialisé (queue.h:8-13) → au 1er move, distance = pos - garbage ; si garbage == pos →
   NaN/crash. L'app déduplique les positions consécutives mais pas la 1re (lastStreamPos=-1).
3. **Écrasement depth par l'encodeur** en streaming (playControl==DEPTH) : si le bouton physique
   encodeur n'est pas à 100, `settings.depth` dérive sous 99 → bandVerified échoue à l'entrée.
4. **Overriding silencieux du pot** : dès que le pot physique bouge, le flag BLE speed est reset →
   la vitesse redevient celle du pot (re-assertée seulement au commit suivant du slider).
